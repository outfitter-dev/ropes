# Editor settings

Indent, line endings, charset and line width are facts several tools have to agree on. A repository states them once, in the `[editor]` table of the Cinch config, and Cinch writes the root `.editorconfig` from it.

`.editorconfig` cannot extend another file and editors only read it from the repository's own folders. So it cannot follow the preset, generated, root chain the tool configs use. Cinch writes the whole file instead.

## The table

```toml
[editor]
charset = "utf-8"
indent_style = "space"
indent_size = 2
end_of_line = "lf"
final_newline = true
trim_trailing_whitespace = true
line_width = 100

# Facts for some files. A later entry wins over an earlier.
[[editor.overrides]]
files = ["Makefile", "*.mk"]
indent_style = "tab"
```

Every key is optional. Cinch writes only what the table states, and ships no defaults of its own here. Two keys have other names in the file: `final_newline` becomes `insert_final_newline`, and `line_width` becomes `max_line_length`. An override with several globs gets one section for each. An unknown key is an error, as everywhere in the Cinch config.

## Who writes the file

- `cinch doctor --fix` writes `.editorconfig`. `cinch check` and `cinch doctor` report it when it is missing or differs from the table, and the finding says to make the change in `[editor]`.
- `cinch fix` never writes it. Like every file Cinch keeps, a stale one stops `fix` until `cinch doctor --fix` has run.
- The file starts with a "Generated by Cinch" line. A file without that line was written by a person, and Cinch never overwrites it. The finding asks for its settings to be moved into `[editor]` and the file to be deleted, after which `cinch doctor --fix` writes the generated one.
- `cinch init` writes it too, when the config that is already there has an `[editor]` table.
- A config that states `[editor]` and also excludes `.editorconfig` is an error, for `doctor` and for `fix`: Cinch cannot keep a file the config leaves out.
- Without an `[editor]` table, `.editorconfig` is not Cinch's. It is left alone and is no part of the setup.

## Not yet

- `cinch init` does not yet read an existing `.editorconfig` into the table. Move the values by hand.
- Cinch does not yet hold files to these facts. The checks that will do so read the same table, so there stays one source.
- A key the table does not know, such as `tab_width`, cannot be stated.
