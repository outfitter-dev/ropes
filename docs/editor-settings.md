# Editor settings

Indent, line endings, charset and line width are facts several tools have to agree on. A repository states them once, in the `[editor]` table of the Ropes config, and Ropes writes the root `.editorconfig` from it.

`.editorconfig` cannot extend another file and editors only read it from the repository's own folders. So it cannot follow the preset, generated, root chain the tool configs use. Ropes writes the whole file instead.

## The table

```toml
[editor]
charset = "utf-8"
indent_style = "space"
indent_size = 2
end_of_line = "lf"
final_newline = true
trim_trailing_whitespace = true
line_width = 100

# Facts for some files. A later entry wins over an earlier.
[[editor.overrides]]
files = ["Makefile", "*.mk"]
indent_style = "tab"
```

Every key is optional. Ropes writes only what the table states, and ships no defaults of its own here. Two keys have other names in the file: `final_newline` becomes `insert_final_newline`, and `line_width` becomes `max_line_length`. An override with several globs gets one section for each. An unknown key is an error, as everywhere in the Ropes config.

## Checking files

Set `check = true` in `[editor]` to check selected files that have no active formatter. The built-in text adapter checks the declared facts directly. Editor enforcement is an explicit adoption choice.

Bun's formatter owns its supported JavaScript, TypeScript, JSON, YAML, TOML, Markdown, CSS, HTML and related extensions while `format.enabled` is true. rumdl owns Markdown while `markdown.enabled` is true. Taplo checks TOML syntax and schemas, so an unformatted TOML file can still receive the editor check. Python, shell, plain text and extensionless files can receive it too, when selected by the repository's include policy. A formatter disabled by a path override leaves that path eligible. Setup files are checked by their setup adapters.

`explain` shows each selected editor check. The adapter reads the same typed facts used for generation and applies matching editor overrides in order, replacing only stated keys. A section glob without a slash matches basenames at any depth. A slash makes it root-relative. The matcher supports brace alternatives, numeric ranges and double stars across directories. Authored root and nested `.editorconfig` files do not replace the declared table in this check. Setup validation separately reports root configuration drift.

Findings name the editor setting, such as `indent_style` or `final_newline`, and identify its line. Whole-file findings point at line one. CR, LF and CRLF delimit logical lines without a line-length limit. Empty text has no final-newline requirement. Leading indentation uses the declared spaces or tabs. Indentation size is a multiple of the declared columns even when style is unstated, and tabs advance by that size. These are whitespace conventions without language-sensitive continuation alignment. Line width uses Bun's Unicode display width, with tab stops equal to `indent_size` or eight columns when size is absent. Blank lines are exempt from indentation checks and still receive trailing-whitespace checks.

The declared charset selects strict decoding for UTF-8, UTF-8 with a BOM, UTF-16LE, UTF-16BE or Latin-1. Conflicting or missing required BOMs and invalid declared encodings are charset findings. Without a declared charset, a BOM selects UTF-16 or UTF-8, otherwise text must decode as UTF-8. Undecodable input and binary control characters make the check incomplete. The checker validates compatibility with the declared encoding and performs no heuristic charset detection. Use the ordinary include and exclude policy to scope selected text.

`check` and `fix` report these findings without repairing files. A formatter that ignores a selected file remains incomplete through its existing coverage check. Disable that formatter for the path through a policy override to select the editor fallback.

## Who writes the file

- `rope doctor --fix` writes `.editorconfig`. `rope check` and `rope doctor` report it when it is missing or differs from the table, and the finding says to make the change in `[editor]`.
- `rope fix` never writes it. Like every file Ropes keeps, a stale one stops `fix` until `rope doctor --fix` has run.
- The file starts with a "Generated by Ropes" line. A file without that line was written by a person. Ropes overwrites it in one case only: it states exactly what `[editor]` states and holds nothing else, so nothing is lost. Otherwise the finding asks for its settings to be moved into `[editor]` and the file to be deleted, and names what the table cannot hold. After that `rope doctor --fix` writes the generated one.
- `rope init` writes it too, when the config that is already there has an `[editor]` table.
- A config that states `[editor]` and also excludes `.editorconfig` is an error, for `doctor` and for `fix`: Ropes cannot keep a file the config leaves out.
- Without an `[editor]` table, `.editorconfig` is outside the managed setup. It is left alone and is no part of the setup.

## Starting from a file you already have

`rope init`, in a repository with no Ropes config and a hand-written `.editorconfig`, reads the file into the `[editor]` table of the config it writes. The `[*]` sections become the base facts, and each other section becomes one `[[editor.overrides]]` entry.

Above the table it writes one `# Not carried over:` line for each thing the table cannot hold:

- a key the table does not know, such as `tab_width`
- a value it does not allow, such as `indent_size = tab` or `max_line_length = off`
- a section whose glob holds `[`, `]`, `#` or `;`
- a `[*]` section below a narrower one, which the generated file could not keep in that place
- anything above the first section other than `root = true`
- what the file takes from a `.editorconfig` in a folder above, when it does not state `root = true`. The file Ropes writes always states it, so add that line first if nothing above should apply
- comments

`rope init` previews both the proposed table and any resulting setup changes. When every authored setting can be represented exactly, applying setup may replace `.editorconfig` with the generated file. When content would be lost, preflight reports the problem and leaves the configuration unchanged. Resolve the reported settings before retrying, or use the explicit adoption command on an existing setup.

`init` does this only for a repository with no Ropes config. For one that has a config, see the next section.

## Adopting a file later

A repository that already has a Ropes config and a hand-written `.editorconfig` moves it over in one step:

```sh
rope preset adopt editor
rope preset adopt editor --yes
```

The first shows the `[editor]` table it would add to the Ropes config and the generated `.editorconfig` that would replace the file. The second writes both. It reads the file the way `init` does.

- It stops, writes nothing and exits 1 when the file states a setting the table cannot hold, such as `tab_width`. It names each one. Take them out, or keep the file by hand.
- It stops the same way when the file does not state `root = true`, because the generated file does and would cut off the settings of a folder above.
- It stops with exit 2 and writes nothing when the Ropes config excludes `.editorconfig`, since Ropes could not keep the file it would write.
- Comments are not carried over. The move says which lines held them.
- When the Ropes config already has an `[editor]` table that states what the file states, only the file is replaced. When the table states something else, it stops: settle the table by hand.
- `rope preset eject editor` moves nothing. To keep the file by hand again, delete the `[editor]` table and the first two lines of `.editorconfig`.

- Ropes does not yet write these facts into other tools' configs. It does report a tool's config that states one differently: see [shared facts](shared-facts.md).
- A key the table does not know, such as `tab_width`, cannot be stated.
